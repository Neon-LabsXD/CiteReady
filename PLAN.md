# CiteReady — план сайту

**CiteReady** — AI Visibility Checker / Перевірка готовності сайту до AI-пошуку.
Публічна адреса: https://ws-109.ws.semalt.dev

## 1. Мета

1. Дати власнику сайту чи SEO-фахівцю швидку безкоштовну діагностику «AI-готовності» (GEO — Generative Engine Optimization): оцінка 0–100 за 10–20 секунд.
2. Перетворити абстрактне «оптимізуйся під AI» на конкретний чекліст дій із прикладами коду.
3. Показати повноцінний міні-застосунок: фронтенд + невеликий PHP-бекенд + зовнішнє API (FreeSerp) + двомовність (EN/UA).

## 2. Аудиторія

- SEO-маркетологи та спеціалісти агенцій — швидка перевірка клієнтського сайту.
- Власники малого бізнесу й стартапів, які чули про «AI-пошук», але не знають, з чого почати.
- Контент-маркетологи, які хочуть, щоб їхні сторінки цитувались у відповідях AI.

## 3. Сторінки та структура

| Сторінка | Вміст |
|---|---|
| `/` | Лендінг + чекер + результати (на тій самій сторінці). Шапка (лого, «Методологія», EN/UA), hero з полем домену, 5 категорій перевірок, «Як це працює» (3 кроки), FAQ (4–6 питань, з FAQPage JSON-LD), футер |
| `/?d=example.com` | Те саме, але перевірка запускається автоматично (посилання для шерингу) |
| `/methodology.php` | Усі перевірки, ваги, джерела даних, застереження, що оцінка — орієнтир, а не гарантія цитування. Двомовно |
| `/api/check.php?domain=…` | JSON API (не для людей) |
| помилки | Зрозумілі EN/UA повідомлення: невалідний домен, недоступний сайт, таймаут, ліміт запитів, 404 |

**Блок результатів:** домен + кругова SVG-діаграма + грейд + вердикт + дата → 5 смуг категорій → картка «Як AI бачить ваш сайт» (ai_summary, ніша, стек, DR) → таблиця AI-ботів → **чекліст рекомендацій** (головний блок) → деталі всіх перевірок (`<details>`) → конкуренти в ніші → дії (копіювати посилання, перевірити інший, друк/PDF).

## 4. Перевірки та оцінка (100 балів)

| Категорія | Бали | Перевірки |
|---|---|---|
| A. Доступ AI-краулерів | 25 | A1 robots.txt (5), A2 AI-боти не заблоковані (15), A3 HTTPS 200 (5) |
| B. Файли для AI | 15 | B1 llms.txt (8), B2 sitemap.xml (7) |
| C. Структуровані дані | 20 | C1 JSON-LD (8), C2 корисні типи schema (7), C3 Open Graph (5) |
| D. Контент і мета | 20 | D1 title (4), D2 description (4), D3 один h1 (3), D4 lang+canonical (3), D5 обсяг тексту (3), D6 питання-відповідь (3) |
| E. Присутність в індексах (FreeSerp) | 20 | E1 є в індексі сайтів (5), E2 AI-опис (5), E3 Domain Rating (5), E4 сторінки в глобальному індексі (5) |

- Статуси: `pass` = 100% ваги, `warn` = 50%, `fail` = 0%, `na` = виключається, бали категорії перераховуються пропорційно з решти (відсутність сайту у FreeSerp не карає).
- Грейди: **A** 85–100, **B** 70–84, **C** 50–69, **D** 30–49, **F** <30.
- Чекліст: усі `fail`/`warn`, відсортовані за втраченими балами; кожна рекомендація — що не так → чому важливо для AI → що зробити (+ приклад коду).
- Ваги й логіка — **дані** у `config/checks.php`, а не розкидані по коду.

## 5. Джерела даних

1. **Власний PHP-бекенд:** `robots.txt`, `llms.txt`, `sitemap.xml`, HTML головної (браузер не може через CORS).
2. **FreeSerp API** (без ключа, `https://freeserp.ai/api.php`), завжди з PHP + кеш:
   - профіль домену (`index=sites`, лише якщо `results[0].domain === domain`),
   - сторінки в глобальному індексі (`index=web`),
   - конкуренти за `ai_categories` або ключовими словами з title.
   - Параметри ідентифікації: `agent=CiteReady/1.0&project=CiteReady&website=https://ws-109.ws.semalt.dev`.
   - Врахувати `engine_fallback: true`; відсутні дані → `na`, не помилка.

База даних **не потрібна** (MariaDB не використовуємо).

## 6. Архітектура

Стек: чистий HTML + CSS + vanilla JS, PHP 8.4 без Composer. Розширення перевірено: curl, dom, libxml, mbstring, intl, SimpleXML — усе є.

**Розміщення файлів (обраний варіант).** `/home/ws` має права `700`, php-fpm (`www-data`) звідти не читатиме, тож код поза webroot кладемо в `/var/www/citeready/`:

```
/home/ws/projects/citeready/        ← робочий репозиторій (джерело правди)
├── public/        → rsync → /var/www/html
├── src/           → rsync → /var/www/citeready/src       (поза webroot)
├── config/        → rsync → /var/www/citeready/config    (поза webroot)
├── storage/       → тільки на сервері: /var/www/citeready/storage (кеш, rate-limit; власник ws, група www-data, запис для групи)
├── deploy.sh, PLAN.md, WORKLOG.md, README.md
```

- Для створення `/var/www/citeready` (власник `root`) потрібен одноразовий `sudo mkdir && chown`. nginx не змінюємо.
- PHP-класи: `Fetcher` (SSRF-захист), `RobotsParser`, `HtmlAnalyzer`, `FreeSerpClient`, `Scorer`, `Cache`. Підключення через `require` з абсолютним шляхом `/var/www/citeready/...`.
- API повертає лише `id` і `status` перевірок; тексти беруться на фронті з `i18n/en.json` / `uk.json` за ключами `checks.A2.warn.title` / `.fix`.
- Помилки: `{"ok": false, "error": "invalid_domain|unreachable|rate_limited|internal"}` + відповідний HTTP-код.

## 7. Безпека

- Валідація hostname регуляркою (без портів, логінів, шляхів); нормалізація `https://www.example.com/page` → `example.com`.
- **SSRF:** DNS-резолв + відхилення приватних/службових діапазонів (IPv4 та IPv6), підстановка перевіреного IP через `CURLOPT_RESOLVE`, лише http/https і порти 80/443, редиректи вручну (макс. 3, кожен перевіряється), таймаут 8 с, ліміт відповіді 2 МБ.
- Rate limit ~10 перевірок/IP/10 хв (файловий лічильник), кеш 1 година за доменом.
- Екранування: `htmlspecialchars` у PHP, `textContent` у JS для даних з API/FreeSerp.
- Файл `CREDENTIALS.txt` не читаємо і не копіюємо.

## 8. Фронтенд

- Мова: `localStorage` (try/catch) → `navigator.language` (uk/ru → UA, інакше EN); оновлює `<html lang>`, title, description; перемикання без перезавантаження.
- Адаптив від 360px, світла/темна тема (CSS-змінні + `prefers-color-scheme`), доступність (label, фокус, `aria-live`), SVG-діаграма оцінки, друк через `window.print()` + print-стилі.
- Сайт сам має отримати високу оцінку: title, description, один h1, lang, canonical, OG, JSON-LD (`WebApplication` + `FAQPage`), robots.txt, llms.txt, sitemap.xml.
